# StormTracker V9.14.0 candidate — contextual source freshness and interaction integrity

## Scope

This branch builds on V9.13.4. It makes incident source problems visible
without changing measured radar, Doppler, 3-D inference, the BoM flood gauge
screen, Queensland state border, or the existing source/polygon filtering rules.

## Operational defects addressed

- On a successful check, QLDTraffic flood closures and Queensland-only
  unplanned power outages now show the **last successfully checked AEST** time.
  This is the browser retrieval time, *not* the provider's incident start,
  update time, or an assertion that the incident is active beyond its feed.
- If the source fails while the last response is recent, show a clearly
  **UNVERIFIED** warning rather than silently treating cached events as fresh.
- If provider retrievals continue failing, cached **QLDTraffic flood closures
  expire at 30 minutes**, and cached **power outages expire at 60 minutes**
  from the last successful refresh. The stale map entities are removed,
  open cards close, and the source visibly reports expiry. No synthetic
  outages or closure polygons are created.
- Source expiry is checked by the normal per-layer timer and when a browser
  tab becomes visible. Toggling layers back on retains the last status
  instead of leaving the false text "hidden".
- Pointer-down handlers for flood closures and electricity now ignore
  other incident information cards, preventing accidental cross-layer
  selection while opening/using QFD/BoM-related context panels.
- Cache-busting has been updated on the production iframe, operational
  controller and stylesheet so an existing browser does not keep running
  old modules with the V9.13.4 semantics.

## Polling and independence

- Flood road closures: existing 5-minute poll; 30-minute max map snapshot age.
- Power outages: existing 15-minute poll; 60-minute max map snapshot age.
- BoM flood gauges: existing separate screening/polling behavior unaffected.
- Different upstream providers remain independent. Partial outages explicitly
  report unavailable layer(s) rather than treating incomplete results as a
  complete provider snapshot.

The source-age cap is a *failure-safety policy*, not a claim that the provider
updates at that exact interval. All operational indicators remain advisory;
official sources and warnings remain authoritative.

## Validation gates

1. Full `npm test` regression suite including new
   `run-source-freshness-v1-tests.mjs`.
2. Verify both incident cards open and official source links remain usable
   with other incident layers switched on.
3. Simulate a failed source refresh: recent incidents must be flagged
   UNVERIFIED; expired incidents must be removed from the map and click state.
4. Browser tab hidden/reopened after the expiry window must clear old incidents
   before continuing refresh, with radar/track state unaffected.
5. Confirm desktop and mobile interactions and performance on real
   Queensland imagery and Street modes.

**Release status:** candidate only until CI and live browser checks pass.
Do not alter the immutable accepted V9.13.4 recovery point without
a successful acceptance and a new restore reference.
