# StormTracker V9.15.0 — QFD published incident groups (draft)

Branch: `feature/v9.15.0-qfd-technical-rescue` (stacked on draft V9.14.0).

## Accepted public-source contract

Only three exact values from the public QFD ESCAD Current Incidents
ArcGIS `GroupedType` field are eligible for this layer:

| Published GroupedType | StormTracker label | Notes |
| --- | --- | --- |
| `RESCUE TECHNICAL` | Technical rescue | No water/vertical/mountain subtype implied |
| `RESCUE ROAD CRASH` | Road crash rescue | Not evidence of a QLDTraffic road closure |
| `ASSIST PUBLIC` | Public assistance | No automatic severe-weather or SES job inference |

The server queries only these values and the browser independently
applies the same allowlist before a marker can be drawn. Records of
all other types, including fire, planned jobs or unrelated groups,
are excluded. Current status, QFD time, approximate locality, and
attendance are taken only from the public feature source.

Publisher: https://www.fire.qld.gov.au/Incident-Dashboard
Source schema: https://services1.arcgis.com/vkTwD8kHw2woKBqV/arcgis/rest/services/ESCAD_Current_Incidents_Public/FeatureServer/0?f=pjson

## Visual symbology and provenance

**Verified 8 October 2026:** The public QFD ESCAD `FeatureServer/0?f=json`
does publish a `drawingInfo.renderer` with the exact three QFD
`GroupedType` entries. All three are `esriPMS` picture markers with
embedded **PNG imageData**. The public ArcGIS FeatureServer returns
`Access-Control-Allow-Origin: *`, suitable for the browser architecture.

The client reads those original PNG samples directly from QFD's publicly
available renderer; no guessed or copied icon shapes are necessary.
The same verified source image is used in the map, legend and incident
information card. The official-symbol lookup completes before the first
incident markers are drawn, avoiding a provisional-to-official flash.

If the source image lookup fails temporarily, the layer uses unmistakably
**labelled provisional** icons (not called official), while existing
incidents continue to follow source-error/expiry protections. No restricted
CAD imagery is accessed. The source verification workflow logs only the
published group names, renderer metadata, PNG lengths and CORS header —
never individual incident records or private dispatch information.

Public source verification workflow:
`scripts/probe-qfd-public-legend.mjs` and
`.github/workflows/probe-qfd-public-legend.yml`.

## Operation

- Layer is optional and OFF by default in this draft.
- Polls every 10 minutes while visible; each successful response replaces
  the previous incident set, removing jobs absent from the provider.
- 30-minute maximum unverified snapshot age; expired markers removed.
- On a recent source failure markers are flagged **UNVERIFIED**;
  first-load failures display **no verified incidents**.
- Non-overlapping map cards and official source links consistent
  with existing road-closure, outage and BoM gauge interactions.
- Runs entirely in the browser / GitHub Pages architecture. No server
  or paid provider is introduced.
- Incident points represent **general areas** only, never exact rescue sites.

## Outside current public scope

Internal QFD problem types (such as `RESCUE VERTICAL`,
`RESCUE WATER ALL TYPES`, `RESCUE MOUNTAIN RESCUE`,
`RESCUE RTC LARGE MULTI`, `ASSIST EXTREME WEATHER`
and `XE RESCUE WATER`) cannot be identified from the publicly
available `GroupedType` field. They must **not** be inferred
from these three broad groups.
