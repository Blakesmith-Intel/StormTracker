======================================================================
1. PROJECT PURPOSE
======================================================================

StormTracker is a browser-native severe-weather/radar product for South East
Queensland.

Core objectives:
- Near-real-time public BOM reflectivity and Doppler display.
- Persistent storm tracking using measured 2-D reflectivity.
- Browser-rendered inferred 3-D storm volumes.
- Doppler radial-velocity context restricted to measured storm footprints.
- Ordinal convective/lightning/severity assessment.
- Historical/test validation mode using a Christmas Night 2023 Gold Coast
  severe-storm scenario.
- No installed backend science engine for the user-facing product.
- Normal product use must be from a web browser.

The current project direction is PRODUCT CONSOLIDATION + OPERATIONAL FEATURES.
Do not return to broad algorithm/science rewrites unless a newly demonstrated
defect requires it.

  inferred/not measured.

- Do not call Doppler horizontal storm motion, total wind speed, or a rotation
  diagnosis by itself.
- Storm identity and horizontal motion are controlled solely by measured
  reflectivity tracking.
- Doppler may contribute to severity/lightning assessment only after being
  time-matched and sampled inside the measured ST footprint.

- area, centroid, max category, etc.

Threshold counts:
- definite >=50: category >=11
- possible >=50: category >=10
- definite >=55: category >=12
- possible >=55: category >=11
- definite >=60: category >=14
- possible >=60: category >=13

Persistent tracking:
- track IDs ST0001...
- 5-minute buckets
- cross-radar dedupe only across DIFFERENT radars
- same-radar observations are never merged in cross-radar dedupe
- time tolerance 180 seconds
- category difference >4 blocks merge
- dedupe radius:
  min(20 km, max(6 km, 1.25*(equiv-radius-sum)+4))
- merged centroid is area-weighted
- sampled merged area = max member area
- transitive same-radar split

Track association:
- geodesic centroid motion
- hard maximum speed 140 km/h
- max gap 12 minutes
- adaptive distance:
  min(45 km, max(10 km, previous radius + current radius + 12 km))
- score:
  0.65*distance_score
  +0.20*area_penalty
  +0.15*category_penalty
  +radar_bonus
- same-radar overlap bonus -0.10
- greedy lowest-score unique matching
- motion is observed centroid displacement only
- motion is NOT Doppler and is NOT a forecast

Tracking confidence:
- >=4 observations + multi-radar -> high
- >=4 otherwise -> medium
- >=2 -> medium
- else -> low

8. 2-D / 3-D GEOREGISTRATION — RESOLVED
======================================================================

A serious N/S offset was diagnosed and fixed.

Root cause:
- BOM mosaic raster is uniformly sampled in EPSG:3857 Web Mercator Y.
- Cesium SingleTileImageryProvider was being fed the raster over a geographic
  lon/lat Rectangle, effectively stretching rows linearly in latitude.
- Near Brisbane/Logan this caused about 5 source raster rows of mismatch.

Fix:
- Resample EPSG:3857 raster rows to geographic-linear latitude before handing
  the image to Cesium.
