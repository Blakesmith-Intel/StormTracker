## Verified preview symptoms (user browser logs)
1. `bindTexture: attempt to use a deleted object` cascades in Cesium, occasionally ending in a full map freeze. Stack traces show GPU-backed `scene.pick` initiated by **power-outage** and **river-gauge** mouse-move handlers; road closures also contain the same polling pattern. Disabling these per-move picks in preview is a mitigation, **not proven correction** of underlying texture disposal.
2. BoM optional recent river-history calls for 529020, 529003 and 527004 return HTTP 502. Backfill runs asynchronously; a preview-only relay error cooldown now prevents repeating the optional requests while leaving current bulletin classification intact.
3. A WMTS tile received HTTP 403, and request pressure guard paused radar cache warming. This identifies upstream rejection, **not its cause**. No replacement or invented BoM observations.
4. Historical storm trails could remain after pausing and disabling Labels. Preview-only frame-rebuild enforcement hides trails and paired ID/centroid DOM markers while preserving the separately controlled selected threat cone. The established V9.16.10 regression contract confirms that independent behaviour. User browser validation remains required.
5. An earlier screenshot showed place labels over a black/empty basemap; this has not been isolated or declared fixed.

## Exact deployment failure sequence
- Actions run **38386252050**: `run-production-shell-v1-tests.mjs` rejected a cache-busted power-outage import because the test expected `v=9.14.0`.
- Actions run **38386903725**: `run-source-freshness-v1-tests.mjs` rejected a cache-busted road-closure import because the test expected `v=9.15.0-unplanned`.
- Failure is **test coupling to hard-coded asset version tokens**. These strings indicate browser cache invalidation, not source semantics, and must not be fixed to a historical value by generic feature tests.
- Replace outdated exact-version checks with validation that intended modules are imported with a non-empty cache-busting query. Preserve functional/data-source tests and immutable release SHA checks.
- `npm test` for the diagnostic branch must run at the **start** of Pages CI, before costly historical preview assembly; the diagnostic test runner aggregates failures so CI reports **all** broken suites in one attempt.
- Only stage the pinned, authenticated preview checkout when the diagnostic tests pass. Production still checks the exact sealed SHA, data snapshot and live build marker independently.
